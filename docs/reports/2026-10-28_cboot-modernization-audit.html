1总体判断

层面结论
核心价值层 不落伍 claude --settings <file> 仍是官方会话级覆盖入口（优先级仅次于 managed settings），Claude Code 至今无原生 profile/多配置切换机制，cboot 存续价值成立 已对抗核查
配置时效层 已落后 teammateDefaultModel 被 v2.1.234 移除后 cboot 仍在 6 处写入；模板停留在 GLM-5.2/glm-4.5-air 世代，官方手动配置示例已推荐 glm-5.3[1m] / glm-5.3-flash[1m] 已对抗核查
工程形态层 形态合理、实践欠账 单文件+双击零依赖分发仍是稀缺有效形态，但零 CI、零 Pester，v1.0.9 BOM 事故无自动化守护，版本号三处维护已实际漂移

分层的含义：不需要重构路线，需要一次「内容对齐 + 防回归守护」的集中维护。

2已被原生覆盖或应收缩的部分

  • 多供应商切换：未被覆盖，保留 已核查
    /model 只能换模型别名并存默认值，不能改 ANTHROPIC_BASE_URL/ANTHROPIC_AUTH_TOKEN；本机 v2.1.308 无 --profile。注意 issue #44687 已于 2026-04-11 作为 #30031 的 duplicate 关闭，诉求由仍 open 的 #30031/#18435 承接——官方若实现原生切换，需重估本项目价值。
  • 权限选择：部分重叠，应升级而非收缩 已核查
    CLI 已有 --permission-mode 六模式（acceptEdits/auto/bypassPermissions/manual/dontAsk/plan，manual 为 default 别名），cboot 仅两态且硬编码 --dangerously-skip-permissions，用户接触不到 plan/acceptEdits/auto。auto/bypassPermissions 不能从 project/local settings 生效，启动器层 --permission-mode 恰是合法注入通道。
  • 会话管理：不自研 已核查
    原生 --resume/Ctrl+A picker 成熟；但官方文档明确 resume 不还原 --settings/--mcp-config/--fallback-model 等启动参数——裸终端续接会丢全部 env 打到错误供应商。因此「目录+套餐+续接」组合启动是 cboot 独有护城河，应做集成而非造轮子。
  • 配置修复：与 claude doctor 对象不同，低重叠，保留 已核查
    claude config 子命令已消失（被当 prompt），文档如有引用需清理。
  • teammateDefaultModel：应收缩删除 已核查
    v2.1.234 移除，现行版本对残留值直接忽略；该键官方作用域本是 Global config（~/.claude.json），写进 settings-*.json 本就错位。

3配置时效问题清单

  1. 死键 已核查 — teammateDefaultModel 在 cboot.ps1 L342/L346/L1329/L1562/L1656/L1658 共 6 处读写，5 个模板均带该字段，初始化向导仍占用一步采集无效值。
  2. 模板跨代 已核查 — 5 个模板 ANTHROPIC_DEFAULT_HAIKU_MODEL 全为 glm-4.5-air（两代旧，且不在官方重定向名单，行为无官方背书）；官方声明 GLM-5.2/5.1 调用「自动切换」至 GLM-5.3、GLM-5-Turbo/4.7 切至 GLM-5.3-Flash——旧模板能跑但名不副实，CLAUDE_PROFILE 显示的也是旧身份。

  5. 可疑枚举 未对抗核查 — ENABLE_TOOL_SEARCH="0" 不在官方取值（unset/true/auto/auto:N/false）内，按字符串真值可能等效开启，与写 0 的意图相反。
  6. Haiku 槽语义冲突 部分核查 — Initialize-Config/Add-Model 默认把 Haiku 槽填成旗舰 ID，而官方定位该槽跑后台任务（ANTHROPIC_SMALL_FAST_MODEL 已 deprecated 由其取代），填旗舰会成倍消耗套餐额度。（模板事实「Haiku 槽均为 glm-4.5-air」已经核查证实，语义推断未单独核查）

confirmed ⑥ 恢复会话（--resume/--continue）不还原 --settings 等启动参数，需重新传入；标准 settings 文件则会重新读取

依据：官方 sessions 文档「恢复时不还原的启动参数」一节

核查修正：成立。补充：(1) 官方「不还原、需重新传入」完整清单为 --mcp-config、--settings、--plugin-dir、--fallback-model、--add-dir；(2) --model 与权限模式通常由会话状态还原，--system-prompt/--append-system-prompt 采用「首次请求时记录进会话」的特殊语义；(3) 实测发现 resume 时 --settings 传入坏端点会导致 CLI 长时间静默重试（>11 分钟无输出）而非快速失败——排查启动配置问题时应先检查 resume 命令是否带错 --settings。

展开完整核查证据
